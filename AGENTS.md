# AGENTS.md — cs2_cutter_ui (фронтенд)

Статический веб-интерфейс сервиса нарезки хайлайтов CS2. Одна страница, без
сборки, без зависимостей, без Node. Раздаётся `python3 -m http.server`.

## Место в системе

Три репозитория, обычно склонированные рядом:

| Репозиторий | Роль | Что требует от машины |
|---|---|---|
| `cs2_cutter_ui` (этот) | интерфейс: `web/index.html` + `web/config.js` | ничего, кроме python3 |
| `../cs2_cutter` | **рендер**: нарезка, запись, CS2 | GPU, Steam, CS2, sway |
| `../cs2_cutter_backend` | **библиотека и авторизация** | ffmpeg |

UI ходит в **два разных сервиса** по двум базовым адресам:

* `API_BASE` → рендер: `/api/session`, `/api/demos`, `/api/upload`,
  `/api/demo/{id}/players`, `/api/jobs`, `/api/events` (SSE),
  `/api/clips/{job}/{file}`, `/api/session/restart`;
* `LIB_BASE` → библиотека: `/api/auth/login`, `/api/auth/steam/login`,
  `/api/auth/me`, `/api/billing/me`, `/api/billing/checkout`, `/api/library`,
  `/api/library/upload`, `PATCH`/`DELETE /api/library/{id}`,
  `/api/library/{id}/file`, `/api/library/{id}/thumb`.

Разделение не косметическое: рендер-хост занят игрой и перезапускается, а
библиотека должна открываться, когда CS2 не запущена. Когда бэкенды сольют,
`LIB_BASE` просто не задают — он по умолчанию равен `API_BASE`.

Адрес каждого: `?api=`/`?lib=` в URL → localStorage → `window.CS2_API_BASE` /
`window.CS2_LIBRARY_BASE` из `config.js` → пусто (тот же origin).

**Рендер-хостов может быть несколько.** Их список ведёт администратор во
вкладке «Админ», хранит библиотека (`GET /api/render-hosts` — включённые,
`/api/admin/render-hosts` — CRUD). `API_BASE` — запасной хост, когда список
пуст. Новая демка загружается на готовый хост с самой короткой очередью
(`pickHost()` по `/api/health`), разбор и задачи по ней идут туда же.
Задачи и их клипы помнят хост в поле `_host`, демки — в `state.demos`;
SSE открыт к каждому хосту. Относительные `file_url`/`zip_url` склеивать
только с хостом своей задачи.

**Адреса сервисов — только во вкладке «Админ».** В шапке у пользователя
только тариф и выход: адреса бэкендов ему ничего не говорят. Состояние
библиотеки и каждого хоста, перезапуск CS2 — в админке.

## Структура

```
web/index.html        вся страница: разметка + CSS + JS в одном файле
web/config.example.js образец конфига (в git)
web/config.js         адрес бэкендов этой установки — НЕ в git, генерируется serve_ui.sh
serve_ui.sh           генерирует config.js из env и поднимает http.server
systemd/              юнит пользователя
```

**Один файл — сознательное решение.** Страница отдаётся `http.server` без
сборки; вводить бандлер или фреймворк значит завести шаг сборки там, где его
специально нет. Новый функционал добавляем в тот же файл, разделяя секциями
`// ---------- имя ----------`, как сейчас.

## Запуск и проверка

```bash
CS2_API_BASE=http://192.168.0.4:8000 CS2_LIBRARY_BASE=http://192.168.0.5:8000 ./serve_ui.sh
# → http://localhost:8080
```

Тестов и линтеров нет — проверка только в браузере. Минимальный прогон после
правки: вход по логину, во вкладке «Админ» хосты в состоянии «CS2 готова», список
демок грузится, библиотека рисуется, заливка своего ролика даёт прогресс,
превью открывается, переименование и удаление отрабатывают. Консоль браузера
должна быть чистой.

Если бэкенда под рукой нет, страница деградирует внятно: во вкладке «Админ»
у хоста будет «недоступен», в библиотеке — `Библиотека недоступна: <адрес>`.

## Правила, которые легко нарушить

**Экранирование.** Названия фрагментов пишет человек. В разметку они попадают
только через `esc()` — кавычка в названии иначе ломает атрибут, а
`<img onerror>` из названия выполнится как скрипт. Это касается и `title`, и
`id` в `data-id`, и URL внутри `src`.

**Токен.** JWT лежит в `localStorage` (`cs2_jwt_token`), обычные запросы идут
через `authFetch()` (заголовок `Authorization`, на 401 — сброс токена и экран
входа). Но `<video src>`, `<img src>`, `<a download>` и `EventSource`
заголовки слать не умеют — для них есть `withToken()`, дописывающий
`?token=`. Не заменяйте одно на другое: и то и другое нужно.

**Вход — через Steam, пароль — только у администратора.** Кнопка Steam
уводит браузер на `/api/auth/steam/login` библиотеки, назад он приходит с
`#token=` (или `#login_error=`) во фрагменте. `takeLoginFromHash()` забирает
токен и сразу стирает фрагмент из адресной строки — иначе токен останется в
истории и в скопированной ссылке. Форма с паролем спрятана в «Вход
администратора». Рендер проверяет тот же токен сам и показывает каждому
только его задачи и демки.

**Тариф и оплата.** Остаток квоты — `/api/billing/me` библиотеки, плашка в
шапке. Способы оплаты приходят оттуда же (`providers`) — не хардкодить: какие
подключены, решает сервер. Paddle открывается оверлеем Paddle.js по
`transaction_id`, созданной сервером (в ней user_id), скрипт грузится только
при оплате. ЮKassa — переход на её страницу и возврат с `?paid=yookassa`.
Премиум включает **только вебхук** провайдера, поэтому после оплаты UI
опрашивает `/api/billing/me` (`waitForPro`), пока не изменится `paid_until`,
а не верит событию оверлея или факту возврата.

**402 от `POST /api/jobs`** — лимит исчерпан: показываем текст сервера и
окно оплаты. Задача с `quota_limited > 0` записала не всё найденное — в её
карточке кнопка «Премиум».

**«Перезапустить CS2» — только администратору**, в его вкладке у каждого
хоста (`role` из `/api/auth/me`): рендер пускает к перезапуску только его.

**Заливка своих видео — `XMLHttpRequest`, а не `fetch`.** У `fetch` нет
прогресса отправки, а ролики под сотню мегабайт: без полосы непонятно, идёт
загрузка или всё зависло. Файлы уходят **строго по очереди** — параллельные
заливки делят один канал, все ползут медленно, и прогресс перестаёт
что-либо значить.

**Лимиты не хардкодить.** Расширения и потолок размера приходят в
`GET /api/library` (`limits`) — они задаются переменной окружения на сервере.

**Фильтры и поиск считает сервер**, поиск с задержкой 300 мс — запрос на
каждую букву не нужен.

**Библиотека обновляется по событиям задачи.** Рендер-хост шлёт клипы в
библиотеку фоном уже после записи, поэтому ждать конца задачи нельзя;
`scheduleLibraryRefresh()` перезапрашивает список не чаще раза в 4 секунды.

**Ссылки на клипы относительные** (`/api/clips/…`) — UI достраивает их сам.
Для чужого origin браузер игнорирует атрибут `download`, поэтому клипы
открываются в новой вкладке; это не баг.

**Сетка фрагментов перерисовывается целиком**, поэтому клики обрабатываются
делегированием на `#frags`, а не обработчиком на карточке.

**`config.js` не коммитить** — это параметр установки. Правится
`config.example.js`.

## Что дальше (см. task1.md)

Планируется редактор вертикальных видео: таймлайн со своей аудиодорожкой и
фрагментами из библиотеки, смена aspect ratio (обрезка по краям или расширение
вверх/вниз). Библиотека — вход в эту фичу: у каждого фрагмента уже есть
разрешение, fps и кодеки, потому что разнородные исходники придётся приводить
к общему знаменателю.

## Стиль

Комментарии по-русски и объясняют **почему**, а не что: почему XHR, а не
fetch; почему по очереди, а не параллельно; почему `esc()`. Это главная
конвенция всех трёх репозиториев — комментарий, пересказывающий код, здесь
лишний, а комментарий, снимающий вопрос «почему не проще», обязателен.

## Когда правка не сюда

Новый эндпоинт, смена формата ответа, лимиты, права — это `../cs2_cutter`
(рендер) или `../cs2_cutter_backend` (библиотека и авторизация). У каждого
свой AGENTS.md.
